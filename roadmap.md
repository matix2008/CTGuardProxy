# COPYTRUST VPS-proxy — roadmap

Источник требований — `docs/SAD-proxy.md`. Пункт выполняется только после согласования открытых вопросов `Q-xx`, перечисленных в нём. Решения по вопросам фиксируются в `spec.md`.

Обозначения: `[ ]` — не выполнен, `[x]` — выполнен. Префикс `Э1`/`Э2`/`Э3` — этап SAD (раздел 5).

[ ] **1.** Э1. Закрыть вопросы Q-01–Q-04 (фактическая конфигурация `CTService`, выпуск и доверие сертификатов, перечень интерфейсов и клиентов, работа PHP с WSDL); решения занести в `spec.md`.

[ ] **2.** Каркас репозитория: структура каталогов для конфигураций, runbook-ов и приёмочных проверок; `.gitignore` для секретов (ключи, PFX, map-файлы с реквизитами, `.env`).

[ ] **3.** Э1. Подготовить конфигурацию HTTPS для `copytrust-svc`: шаблон `CTService.exe.config` (binding `Transport`, metadata по HTTPS) и runbook регистрации сертификата (`netsh http add sslcert/urlacl`) по SAD 3.1.

[ ] **4.** Э1. Подготовить скрипт проверки TLS-участка (цепочка, имя, версии протокола и наборы шифров по политике SAD 2.3), применимый на этапах 1–3.

[ ] **5.** Э1. Runbook переключения сайта на HTTPS: адреса `.env`, явный `location` SOAP-клиента, WSDL/XSD, сброс WSDL-кеша, миграция остальных HTTP-клиентов.

[ ] **6.** Э1. Приёмка этапа 1 по SAD 7: HTTPS работает, недоверенный и неподходящий сертификат отклоняются, HTTP API закрыт; Basic Auth и тайм-аут 30 с без изменений.

[ ] **7.** Меры безопасности `copytrust-svc` по SAD 3.4 (пароль в сообщениях валидатора, `includeExceptionDetailInFaults`, секреты в Release-конфигурации, ротация затронутых реквизитов).

[ ] **8.** Э2. Закрыть вопросы Q-05–Q-10 (параметры VPS-proxy, адреса, тайм-ауты, скорость обнаружения отказа, контракт health check, расчётная нагрузка); решения занести в `spec.md`.

[ ] **9.** Э2. Развернуть VPS-proxy: ОС, HAProxy LTS, непривилегированный пользователь, DNS, серверный сертификат, доступы администраторов, закрытый stats socket.

[ ] **10.** Э2. Конфигурация HAProxy: HTTPS frontend, backend с `ssl verify required`, `verifyhost` и SNI, политика TLS, allowlist Host/методов/маршрутов, запрет CONNECT и недоверенных заголовков идентификации.

[ ] **11.** Э2. Circuit Breaker: HTTPS health check по согласованному контракту, `inter/fall/rise`, тайм-ауты `connect/server/client/http-request/queue`, `retries 0`, лимиты `maxconn`; секрет health check хранится отдельно.

[ ] **12.** Э2. Журналирование HAProxy (SAD 4.5) и ротация с ограничением срока хранения и суммарного объёма.

[ ] **13.** Э2. Тайм-ауты и быстрый выход при транспортных ошибках в `TrustSoapClient` (PHP 7.4) по SAD 2.2: спецификация изменения и проверка.

[ ] **14.** Э2. Переключить `.env` сайта на VPS-proxy; проверить SOAP, WSDL/XSD, REST и отсутствие обхода через адреса в WSDL.

[ ] **15.** Э2. Сценарии отказов и нагрузочная проверка: остановка WCF, блокировка TCP, нарушение TLS, открытый порт без SOAP-ответа, SOAP Fault, длительные операции, недоступность VPS-proxy; измерение T-down, T-fail, T-recovery, N-workers.

[ ] **16.** Э2. Приёмка этапа 2 по SAD 7 и 5; зафиксировать процедуру отката к прямому HTTPS.

[ ] **17.** Э3. Закрыть вопросы Q-11–Q-15 (регламент CA, идентификация и права клиентов, mTLS в клиентах, порядок переключения); решения занести в `spec.md`.

[ ] **18.** Э3. Клиентский CA: регламент и инструмент выпуска, защищённое хранение и резервное копирование ключа CA, выдача сертификатов клиентам.

[ ] **19.** Э3. mTLS на HAProxy: `verify required`, `clients.map`, `client-access.map`, `backend-auth.map`, ACL deny-by-default, подстановка внутреннего `Authorization` по `client_id`.

[ ] **20.** Э3. Проверка изоляции идентификации (сертификат А + реквизиты Б), отказ без backend-реквизитов, отклонение незарегистрированных и запрещённых маршрутов.

[ ] **21.** Э3. Перевести `TrustSoapClient` и остальные клиенты на сертификаты; проверить `ClientID` и права каждого клиента.

[ ] **22.** Э3. Сменить backend-пароли, удалить Basic-реквизиты из клиентов, закрыть прямой доступ к API Timeweb (Windows Firewall, IPv4/IPv6), удалить переходные frontend.

[ ] **23.** Э3. Отработать выпуск, продление, срочный отзыв (включая открытые и возобновлённые TLS-сессии), обновление реестра и восстановление из резервной копии.

[ ] **24.** Э3. Приёмка этапа 3 по SAD 7.

[ ] **25.** Определить требования к развитию VPS-proxy в шлюз аутентификации с Circuit Breaker для `copytrust-svc` и других сервисов; результат — новая редакция SAD по указанию пользователя.

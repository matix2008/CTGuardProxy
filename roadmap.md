# COPYTRUST VPS-proxy — roadmap

Источник требований — `docs/SAD-proxy.md`. Пункт выполняется только после согласования открытых вопросов `Q-xx`, перечисленных в нём. Решения по вопросам фиксируются в `spec.md`.

Обозначения: `[ ]` — не выполнен, `[x]` — выполнен. Префикс `Э1`/`Э2`/`Э3` — этап SAD (раздел 5).

Правило проверки: любое изменение сначала проверяется на тестовом экземпляре `CTServiceDev` (порт PORT2, путь `/RegistrationService/2`) и тестовом `.env` сайта, затем применяется на промышленном `CTService` (порт PORT1, путь `/RegistrationService`). Оба экземпляра работают на одном VPS Timeweb под именем `svc2.copytrust.ru`.

[ ] **1.** Э1. Закрыть вопросы Q-01–Q-04 (фактическая конфигурация `CTService`/`CTServiceDev`, выпуск и доверие серверного сертификата без публичного УЦ, перечень интерфейсов, работа PHP с WSDL); решения занести в `spec.md`.

[ ] **2.** Каркас репозитория: структура каталогов для конфигураций, runbook-ов и приёмочных проверок; `.gitignore` для секретов (ключи, PFX, map-файлы с реквизитами, `.env`).

[ ] **3.** Э1. Аудит интерфейсов и клиентов по исходникам `copytrust-svc` и `copytrust.ru`: REST без аутентификации и без тайм-аутов (`file_get_contents`, `fopen`), назначение `GetCopyrusApplicationDoc` (браузер или сервер), неиспользуемый `SERVICE_URI`, различие путей Dev и Prod, обратный канал `TaskFinished` (svc → сайт: HTTPS, проверка сертификата сайта, TLS 1.2 в .NET Framework 4.7.2). Результат — перечень интерфейсов для allowlist и список отклонений от SAD.

[ ] **4.** Э1. Серверный сертификат `svc2.copytrust.ru` по решению Q-02 (SAN, срок, ключ, хранение, ротация): установка в `LocalMachine\My` и распространение доверия на все клиенты сайта (`SoapClient`, `file_get_contents`, `fopen`).

[ ] **5.** Э1. Dev: HTTPS для `CTServiceDev`: шаблон конфигурации (binding `Transport`, metadata по HTTPS, REST по HTTPS), регистрация сертификата и URL ACL (`netsh http add sslcert/urlacl`), корректный адрес в WSDL (SAD 3.1).

[ ] **6.** Э1. Скрипт проверки TLS-участка (цепочка, имя, версии протокола и наборы шифров по политике SAD 2.3), применимый на этапах 1–3.

[ ] **7.** Э1. Dev: переключить тестовый `.env` сайта на HTTPS, задать явный `location` SOAP-клиента, сбросить WSDL-кеш; проверить SOAP, WSDL/XSD, REST и обратный канал `TaskFinished`.

[ ] **8.** Э1. Prod: runbook и выполнение жёсткого переключения (HTTP.sys не обслуживает HTTP и HTTPS на одном порту): окно, синхронная смена конфигурации `CTService` и `.env` сайта, откат; отключить неиспользуемые интерфейсы (TextSearch на порту 80, адреса `CTPartnerService`).

[ ] **9.** Э1. Приёмка этапа 1 по SAD 7: HTTPS работает, недоверенный и неподходящий сертификат отклоняются, HTTP API закрыт; Basic Auth и тайм-аут 30 с без изменений.

[ ] **10.** Меры безопасности `copytrust-svc` по SAD 3.4 (пароль в сообщениях валидатора, `includeExceptionDetailInFaults`, секреты в Release- и Debug-конфигурациях, ротация затронутых реквизитов).

[ ] **11.** Э2. Закрыть вопросы Q-05–Q-10 (параметры VPS-proxy, адреса, тайм-ауты, скорость обнаружения отказа, контракт health check, расчётная нагрузка); решения занести в `spec.md`.

[ ] **12.** Э2. Развернуть VPS-proxy: ОС, HAProxy LTS, непривилегированный пользователь, DNS, серверный сертификат, доступы администраторов, закрытый stats socket.

[ ] **13.** Э2. Конфигурация HAProxy: HTTPS frontend, backend с `ssl verify required`, `verifyhost` и SNI, политика TLS, allowlist Host/методов/маршрутов (Dev и Prod), ограничение входа по egress IP сайта, запрет CONNECT и недоверенных заголовков идентификации.

[ ] **14.** Э2. Circuit Breaker: HTTPS health check по согласованному контракту, `inter/fall/rise`, тайм-ауты `connect/server/client/http-request/queue`, `retries 0`, лимиты `maxconn`; секрет health check хранится отдельно.

[ ] **15.** Э2. Журналирование HAProxy (SAD 4.5) и ротация с ограничением срока хранения и суммарного объёма.

[ ] **16.** Э2. Локальный версионируемый комплект WSDL/XSD с явным `location`, чтобы отказ backend не задерживал создание `SoapClient` (SAD 2.1, Q-04).

[ ] **17.** Э2. Индивидуальные тайм-ауты и быстрый выход при транспортных ошибках в `TrustSoapClient` (SOAP) и REST-клиентах сайта (SAD 2.2); существующие `connection_timeout=5` и `default_socket_timeout=30` — базовые значения.

[ ] **18.** Э2. Переключить `.env` сайта на VPS-proxy (сначала Dev, затем Prod); проверить SOAP, WSDL/XSD, REST и отсутствие обхода через адреса в WSDL.

[ ] **19.** Э2. Сценарии отказов и нагрузочная проверка: остановка WCF, блокировка TCP, нарушение TLS, открытый порт без SOAP-ответа, SOAP Fault, длительные операции, недоступность VPS-proxy; измерение T-down, T-fail, T-recovery, N-workers.

[ ] **20.** Э2. Приёмка этапа 2 по SAD 7 и 5; зафиксировать процедуру отката к прямому HTTPS.
